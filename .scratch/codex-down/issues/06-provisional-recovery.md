# 06: Provisional GOs are tracked in a list that survives restarts

**What to build:** a provisional GO (08) is only a loan. This ticket keeps every PR that holds only one in a durable list in the boss's tracker, written before the comment is posted, so no provisional GO can exist that the list does not know about. It also says when an entry is removed. Re-reviewing the entries with Codex, the post-merge NO-GO and the release stop are 10.

**Scope:** new on 2026-10-04, split out of the original ticket 04 at the boss's request, after Codex review 1 of the plan and the owner-accepted premortem (R19, R25); split again after Codex review 3 (findings 5, 16, 23) into 06 (the list) and 10 (the recheck and the release stop). The gate that refuses provisional and waived GOs on deploying branches is 04. **Why this ticket does not wait for 04:** it needs 08's provisional records and `kind` field, and 05's `tracker.update` with its return contract, and it reads and writes nothing that `boss_merge.py` owns.

**Blocked by:** 05 (A dead reviewer becomes an open blocker), 08 (The fallback review, labelled and provisional)

**Status:** ready-for-agent

The list (R19, finding 5):

- [ ] When `boss_review.py` records a provisional GO it first writes one line under a `## Provisional GO` section of the track's tracker (`tracker.insert_in_section` creates the section), then posts: `- [prov owner/repo#N] head=<sha> round=<NN> base=<branch> at=<iso>`. In 02's order the write sits after the round is claimed and its `.out` written, before the post. The line is keyed by its `[prov owner/repo#N]` tag, `owner/repo` being 02's `repo_key`: a later provisional GO on the same PR replaces the line (a new head, a new round) inside one `tracker.update`, and never adds a second. The write counts only if `tracker.update` returned `done` and the entry reads back from the file; otherwise nothing is posted, the round is `list-failed` (verdict kept in the JSON) and the exit is 7. A `gh pr comment` that fails after a good entry leaves the entry in place (round `post-failed`, exit 7): 10's recheck clears it. State lives only in the tracker file: a test writes the entry in one process and reads it in another
- [ ] **No track, no provisional review:** the fallback is passed to the chain only when `--track T` is valid (05's rule) and names a tracker that is a regular file under `pm/`; otherwise the review runs Codex only, a Codex failure ends with exit 4 and `claude` is never called, and stderr says the fallback needs a track. 08's tests that expect the fallback now pass `--track`, and so does any test in 05 or 09 that expects it. A provisional NO-GO writes no entry

Removal:

- [ ] A function `prune_provisional(track, repo)` in `skills/boss/boss_review.py` removes an entry, inside one `tracker.update`, when the highest-numbered posted round of that PR with `kind` `codex` **and** a `head_sha` equal to the entry's `head=` is a `GO` with a number above the entry's `round=` (Codex has since said GO on the head that was reviewed, and no later Codex round on it says otherwise). For an entry whose PR is open (read with `gh pr view --repo R --json state,headRefOid`) it also removes the entry when the highest-numbered posted `kind: codex` round on the PR's live head is a GO, because the entry's head no longer merges. A Codex GO on a later head never removes the entry of a merged PR (finding 16); a Codex NO-GO never removes an entry through this function (10's post-merge blocker removes its own entry after writing the blocker); a PR whose state cannot be read keeps its entry. 10's recheck calls it at the start of every pass and after each review in it

Tests:

- [ ] Tests use real `git` where a checkout is needed, and 01's stub-directory harness with its PATH guard (`codex`, `claude`, `gh` and `boss-alert` stubs, a temp `HOME` and `CLAUDE_CONFIG_DIR`, `BOSS_TYPESAFE_ENV` pointing at a missing file): each test asserts its stub call logs and fails if `codex`, `claude` or `gh` resolves outside the stub directory [R25]. Cases: the entry written in one process and read in another; replace-on-new-head leaves one line; `update` failing (unwritable tracker) gives exit 7, nothing posted and a `list-failed` round; a failing `gh pr comment` after a good entry keeps the entry; each removal row (GO on the entry's head and a later round removes; that GO followed by a later Codex NO-GO on the same head keeps; GO on a later head of a merged PR keeps; the same GO on an open PR removes; NO-GO keeps; an unreadable PR state keeps); Codex down and no `--track` gives exit 4 with the `claude` log empty
