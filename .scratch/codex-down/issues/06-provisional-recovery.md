# 06: Provisional GOs are tracked in a list that survives restarts

**What to build:** a provisional GO (08) is only a loan. This ticket keeps every PR that holds only one in a durable list in the boss's tracker, written before the comment is posted, so no provisional GO can exist that the list does not know about. It also says when an entry is removed. Re-reviewing the entries with Codex, the post-merge NO-GO and the release stop are 10.

Removal:

- [ ] A function `prune_provisional(track, repo)` in `skills/boss/boss_review.py` removes an entry, inside one `tracker.update`, in three cases. A PR whose state cannot be read (`gh pr view` fails) keeps its entry under every case below, rule 1 included. Rule 1: when the highest-numbered posted round of that PR with `kind` `codex` **and** a `head_sha` equal to the entry's `head=` is a `GO` with a number above the entry's `round=` (Codex has since said GO on the head that was reviewed, and no later Codex round on it says otherwise). Rule 2: for an entry whose PR is open and whose live head differs from the entry's `head=` (read with `gh pr view --repo R --json state,headRefOid`; the round files are `reviews/<repo_key>/pr<N>/round<NN>.json`, read as `_keep_and_post` writes them) it removes the entry when the highest-numbered posted `kind: codex` round on the live head is a GO (an older Codex GO on the entry's own head never removes through this rule: rule 1's "above the entry's round" is the only test there), because the entry's head no longer merges. A Codex GO on a later head never removes the entry of a merged PR (finding 16); a Codex NO-GO never removes an entry through this function (10's post-merge blocker removes its own entry after writing the blocker); a PR whose state cannot be read keeps its entry. Rule 3: a PR whose state is `CLOSED` without a merge (it will never merge; `gh pr view --json state` says `CLOSED`, a merged one says `MERGED`) loses its entry, since neither 10's recheck nor rule 1 can reach it and 10's release stop would never lift (a reopened PR gets a new entry from its next provisional GO). 10's recheck calls it at the start of every pass and after each review in it. `fn` does no I/O: the PR states and the round records are read first, and `fn` removes only the entries whose line is still the one that was read (16 finding 3: `update` turns only an `OSError` or `UnicodeDecodeError` from `fn` into `failed`; any other exception escapes `_keep_and_post`, which catches `OSError` only, and leaves an empty round). The function takes the tracker's lock and never the PR's lock (`_keep_and_post` takes the PR's lock and then the tracker's, never the other order). It returns the removed tags
