# 06: Provisional GOs are tracked, and Codex re-reviews them

**What to build:** a provisional GO (03) is only a loan. This ticket keeps every PR that holds only one in a durable list in the boss's tracker, and when Codex answers again it re-reviews each of them on the head that was reviewed or merged. A Codex NO-GO on a PR that already merged becomes a dispatched fix, or an open blocker on the ladder when no author can take it. A release or wrap-up stops while the list is not empty.

**Scope:** new on 2026-10-04, split out of the original ticket 04 at the boss's request, after Codex review 1 of the plan and the owner-accepted premortem (R16 to R20, R25). The gate that refuses provisional and waived GOs on deploying branches is 04. **Why this ticket does not wait for 04:** it needs 02's `review()`, 03's provisional records and `kind` field, and 05's `tracker.update`, `tracker.add_line` and blocker format, and it reads and writes nothing that `boss_merge.py` owns, so it can be built side by side with 04. Recovery is Codex-only: a re-review never falls back to Claude.

**Blocked by:** 03 (Labelled fallback review), 05 (A dead reviewer becomes an open blocker)

**Status:** ready-for-agent

The list (R19):

- [ ] When `boss_review.py` records a provisional GO it first writes one line under a `## Provisional GO` section of the track's tracker (`tracker.insert_in_section` creates the section), then posts: `- [prov owner/repo#N] head=<sha> round=<NN> base=<branch> at=<iso>`. The line is keyed by its `[prov owner/repo#N]` tag: a later provisional GO on the same PR replaces the line (a new head, a new round) inside one `tracker.update`, and never adds a second. **No track, no provisional review:** the fallback is passed to the chain only when `--track T` names a tracker that is a regular file under `pm/`; otherwise the review runs Codex only, a Codex failure ends with exit 4 and `claude` is never called, and stderr says the fallback needs a track. So no provisional GO can exist that the list does not know about. 03's and 05's tests that expect the fallback now pass `--track`. State lives only in the tracker file: a test writes the entry in one process and reads it in another
- [ ] An entry is removed when the highest-numbered `status: posted` round of that PR with `kind` `codex` is a GO and its round number is higher than the entry's `round=` (Codex has since reviewed the PR and said GO). A Codex NO-GO after the entry's round does not remove it. The check runs at the start of every recheck pass and after each review in it

The review function (R17):

- [ ] 02's `boss_review.review(...)` gains two optional parameters: `head_sha`, a fixed commit to review (the PR's live head is then not compared with it, because a merged PR's head is no longer the thing being decided; the checkout's HEAD must still equal it, and the brief, the round record and the comment name it) and `allow_fallback` (default true; the recheck passes false). The CLI is unchanged. A test shows a merged PR whose live head differs from the reviewed SHA is reviewed and posted, and an open PR still exits 6 when its head moves

The recheck (R17, R18):

- [ ] `skills/boss/boss_recheck.py --track T --repo OWNER/REPO --checkout DIR` takes the entries of that repo one at a time with no entry able to stop or erase another, and for each calls `review(..., allow_fallback=False, track=T)` so 05's health sync runs. An open PR is reviewed on its live head, a merged PR on the SHA recorded in its entry. The review always runs in a detached temporary worktree outside `--checkout` (`git fetch origin <sha>`, `git worktree add --detach`, HEAD verified equal to the SHA, removed afterwards even when the review fails, leftovers pruned at the start of a pass), so a deleted or advanced branch cannot change what is reviewed and the shared checkout is never moved. Outcomes: Codex GO removes the entry; Codex NO-GO on an open PR leaves it and prints `NO-GO <repo>#<N> round <NN> author=<name>` for the boss to dispatch; no Codex answer, or a fetch that fails, leaves it and goes on to the next entry
- [ ] A Codex NO-GO on a merged PR (R20) writes an open blocker first, then removes the entry, so a crash between the two leaves the entry and the next pass finds the blocker and does not add another. The blocker is one line under the first `## Open blockers`: `- Codex NO-GO on merged <repo>#<N> (round <NN>) - T+0 <ts> [ladder id=fx<8 hex of sha1 of "<repo>#<N>"> t0=<ts> last=0 next=<t0 + 5 min> ask="<action>"]`, built with `tracker.render_marker`, written with `tracker.add_line` (dedupe on the marker's id), followed by `boss-alert 0` once. `<action>` names the PR and the round's `.out` file under `pm/reviews/` and says to dispatch its author or any free worker. The recheck prints `DISPATCH <repo>#<N> author=<name> round=<NN>`. The blocker is the guaranteed minimum: the ladder raises it with no boss turn even when no author session exists, and it stays open until the fix has merged on a Codex GO, then the boss sets `cleared=` and posts `boss-alert clear`

Trigger and release stop (R16):

- [ ] `skills/boss/SKILL.md` says: run `boss_recheck.py` for each repo that has entries whenever a Codex review answers and at wrap-up; on a `DISPATCH` line, dispatch the author or any free worker with the round file as the brief; **wrap-up (Phase E) and any release request (a version bump, a tag, a publish, a reinstall) stop while the list is not empty**, and the boss tells the owner which PRs. `boss_recheck.py --track T --list` prints the entries and exits 0 when there are none and 1 when there are. A text test finds the trigger, the dispatch rule and the stop; a command test checks both exit codes

Tests:

- [ ] Tests use real `git` in throwaway repos with a local bare origin, and 01's stub-directory harness with `codex`, `claude`, `gh` and `boss-alert` stubs, a throwaway `CLAUDE_CONFIG_DIR` and `HOME`, and its PATH guard: each test asserts its stub call logs and fails if `codex`, `claude` or `gh` resolves outside the stub directory [R25]. Cases: three entries where the middle review times out (the other two are handled and the middle stays); a merged PR whose branch was advanced or deleted after the record (the stub's working directory HEAD equals the recorded SHA, the shared checkout's HEAD and files are unchanged, the temporary worktree is gone); a merged PR with a Codex NO-GO gives a blocker that passes `tracker.scan_marker`, `tracker.validate` and `tracker.blockers_range` and that `routines/boss_ladder_core.py --now <t0 + 6 minutes>` raises at rung 5; a crash between the blocker and the removal (blocker already present) adds no second one; the removal rule; the replace-on-new-head rule; Codex down and no `--track` gives exit 4 with the `claude` log empty
