The list (R19, finding 5):

- [ ] When `boss_review.py` records a provisional GO it first writes one line under a `## Provisional GO` section of the track's tracker (`fn` creates the section), then posts: `- [prov owner/repo#N] head=<sha> round=<NN> base=<branch> at=<iso>`. In `_keep_and_post` the write sits after `claim_round`, `append_attempts` and `write_out` (:996-1000) and the head check, before `_post` (:1006, in the `elif` chain from :1001); it happens only for a round that would be `posted` with `kind` `provisional` and `verdict` `GO` (a `head-moved` or `no-verdict` round, a provisional NO-GO and a Codex round write no entry), under the PR's lock, the tracker's own lock being taken inside it (this order, PR lock then tracker lock, is the only one: `codex_blocker.sync` runs outside the PR lock and never takes it). The line is keyed by its `[prov owner/repo#N]` tag, `owner/repo` being 02's `repo_key`: a later provisional GO on the same PR replaces the line (a new head, a new round) inside one `tracker.update`, and never adds a second. The write is `tracker.update(path, fn, deadline)` with `deadline = time.monotonic() + job.io_timeout` (`review()`'s `io_timeout`, default `policy.REVIEW_IO_TIMEOUT`, 60 s: the ladder holds the tracker's lock through a `boss-alert` call of up to 20 s per marker, so a shorter wait would throw a good fallback GO away); `_keep_and_post` gains the tracker path (from `usable_tracker`, resolved once in `review()`) as a new keyword parameter, `_Job` staying without a track as 05c left it; `review()` alone resolves the path with `usable_tracker` and says the "fallback needs a usable track" message once; `main()` passes `allow_fallback=args.track is not None` and calls `usable_tracker` itself nowhere, so a bad track stays `review()`'s `ValueError` and exit 2, and `usable_tracker`'s own "no blocker can be raised" line is not printed a second time by `main()`. A provisional GO that reaches `_keep_and_post` with no tracker path is `list-failed`, exit 7, nothing posted (a defensive rule). `fn` does no I/O of its own: an exception other than `OSError` or `UnicodeDecodeError` raised in it escapes `_keep_and_post`, which catches `OSError` only (:1014), and leaves an empty round. `fn` matches only lines of the exact form `- [prov owner/repo#N] head=...` and, if the section is missing, creates it with the file's own line ending (`insert_in_section` writes LF; CRLF tracker test). The section sits at the end of the file, so a later `boss-tracker append` lands inside it: the entry parser reads only lines of that exact form. Stale text this ticket rewrites: the docstrings at `boss_review.py` :1028-1030 and :1105 and `test_boss_review_provisional.py` :10 and :175 (`test_the_command_line_cannot_reach_the_fallback`, renamed to say the command line without `--track` cannot reach it). The write counts only if `tracker.update` returned `done` and the entry reads back from the file; otherwise nothing is posted, the round's `status` is `list-failed` (a new value beside `posted`, `head-moved`, `no-verdict`, `post-failed`; `verdict` is kept in the record) and the exit is `EXIT_INFRA`, 7. After the write the live head is read once more (as the head check before it did); if the PR moved meanwhile, the round is `head-moved`, nothing is posted, and a second `tracker.update` removes exactly the line this round wrote (matched by tag, `head=` and `round=`, so a newer line is never touched); if that cleanup fails the entry stays (an entry for a comment never posted is harmless: 10's recheck clears it) and the round is still `head-moved`. A test moves the head during the tracker write (the stub `gh` answers a new `headRefOid` on its second call). A `gh pr comment` that fails after a good entry leaves the entry in place (round `post-failed`, exit 7): 10's recheck clears it. The `fn` given to `tracker.update` replaces by tag inside the `## Provisional GO` section only (a tag in prose or in another section is not a match; two lines with one tag, left by a hand edit, become one), and its test runs on a tracker with CRLF line endings.
