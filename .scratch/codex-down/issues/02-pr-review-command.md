# 02: PR review becomes a command

**What to build:** today the PR gate is prose in the boss skill: each worker types `codex exec` by hand. This ticket gives the worker one command, `skills/boss/boss_review.py`, that reviews one PR head. It runs Codex read-only through 01's chain (Codex only: the fallback is 08's), numbers and keeps each round on disk outside the repo, and posts a minimal `Codex review N (run by <name>)` comment on the PR with the head SHA and the verdict. Every outage now passes through one place where it can be seen and counted.

**Scope:** amended 2026-10-04 after Codex review 1 of the plan (finding 1), the owner-accepted premortem (R3 in part, R5 to R7, R9, R25) and Codex review 3 (findings 4, 9, 13, 14, 17, 22, 23). Review 3 split the original 02: the brief's fence, the findings lines, the redaction and the skill text are 07, which comes after this ticket. This ticket posts only fixed words, the head SHA, the verdict and a validated author name, so it can leak nothing. 02 defines the round record and the attempts log that 04, 05, 06, 08 and 09 read. Plan reviews stay hand-run.

**Blocked by:** 01 (One reviewer chain, shared)

**Status:** ready-for-agent

Command and identity:

- [ ] `boss_review.py --repo OWNER/REPO --pr N --checkout DIR --author NAME`. Exit codes: 0 GO posted, 2 usage, identity mismatch or an invalid name, 3 NO-GO posted, 4 no verdict (Codex `absent`, `timeout`, `error` or `noverdict`), 6 head moved, 7 infrastructure failure (the cases below). Exit 5 is 09's (`--waive` refused) and is never used here. `--repo` is required and never inferred from the working directory; `<owner>`, `<repo>` and `--author` match `^[A-Za-z0-9._-]+$` (test: `../x`), else exit 2 with nothing claimed or posted [R7, R9]
- [ ] Identity and head come from one read, `gh pr view N --repo R --json number,url,headRefOid,baseRefName`. Identity holds iff `number == N` and the URL path is `/<owner>/<repo>/pull/<N>` with owner and repo compared case-insensitively with `--repo`; else exit 2, nothing claimed, nothing posted. `gh pr view` exiting non-zero, printing something that is not JSON, or lacking a field: exit 7, nothing claimed. `--checkout`'s HEAD must equal `headRefOid` (else exit 2) and the brief names it. Every `gh pr` call carries `--repo`; every `gh api` endpoint starts `repos/<owner>/<repo>/` with the validated names; both are asserted from the `gh` stub's call log [R5, R7]. Each `gh` call and the lock wait below are bounded by `REVIEW_IO_TIMEOUT = 60` (a `policy.py` constant); a timeout is exit 7
- [ ] The chain call is 01's, Codex only (no fallback), verdict words `GO`/`NO-GO`, the strict flag on, with `REVIEW_CODEX_TIMEOUT = 600` and `REVIEW_FALLBACK_TIMEOUT = 600` added to `policy.py` (a Codex review of this plan took 8 minutes; 03 uses the second). The logic is a function, `boss_review.review(...)`, that the CLI wraps. 05 adds its `track` parameter, 10 adds `head_sha` and `allow_fallback`, and 10's recheck calls it (no second copy) [R3 in part]

Rounds and the record:

- [ ] Per round, under `$CLAUDE_CONFIG_DIR/pm/reviews/<owner>/<repo>/pr<N>/`: `round<NN>.json` and `round<NN>.out` (the reviewer's full answer). Directories 0700, files 0600, never under `--checkout`; the command deletes nothing. The JSON holds repo, pr, round, head_sha, base, reviewer, model, `kind` (`codex` | `provisional` | `waived`; 02 writes `codex`, 08 adds `provisional`, 09 `waived`), verdict (`GO` | `NO-GO` | null), `status` (`posted` | `head-moved` | `no-verdict` | `post-failed` | `list-failed`; 02 writes the first four, `list-failed` is 06's), author, ts and attempts. Every attempt of every run, answered or not, also appends one line to `pm/reviews/attempts.jsonl` in a single `O_APPEND` write: ts, repo, pr, round, reviewer, reason (01's closed set), exit code for `error`, no output text. 05 derives its counts from this log [R9]
- [ ] The review runs first; the round is claimed at the end of the run, whatever the outcome (GO, NO-GO, no verdict, head moved). The command takes a `flock` on `pr<N>/.lock` (0600), re-reads the live head, claims the next free `round<NN>.json` with `O_CREAT|O_EXCL`, appends the run's attempts (each line now carries the round number), writes `round<NN>.out`, posts, replaces the claimed file with the full JSON by temp file and rename, and releases the lock. So numbers follow posting order, "highest wins" means "last posted verdict", and each comment's number equals its file's. A head that moved at the re-read: exit 6, nothing posted, round `head-moved` [R5, R6, finding 13]
- [ ] Exit 7 and what each leaves: `gh pr view` failed (nothing claimed); a round, attempts or lock file that cannot be written before the post (nothing posted); `gh pr comment` failed (round `post-failed`, the verdict kept in the JSON); the final write failing after the post. A crash between the claim and the final write leaves an empty claimed file, which 04's gate treats as `bad-record` and the next round supersedes. When the chain gives `none`: exit 4, nothing that reads as a verdict is posted, the round is `no-verdict`, the attempts are logged. The comment is `Codex review N (run by <name>)`, the head SHA and the verdict, no free text

Tests:

- [ ] Tests use 01's stub-directory harness (moved to a shared test helper if 01 left it inside one test file): `codex` and `gh` stubs, a `claude` stub whose call log must stay empty (no fallback here), `HOME` and `CLAUDE_CONFIG_DIR` in a temp dir, and `BOSS_TYPESAFE_ENV` pointing at a file that does not exist (no ticket in this track calls TypeSafe; `boss-jev.py` is the only module that reads that key, and a stray call would find none). Each test asserts its stub call logs and fails if `codex`, `claude` or `gh` resolves outside the stub directory [R25]. Cases: GO, NO-GO, Codex timeout (1-second test value), Codex `noverdict`, head moved, identity mismatch (wrong `number`, wrong URL path, a different case that still matches), `gh pr view` failing, not JSON and missing a field, `gh pr comment` failing, an unwritable round directory, a crash leftover superseded by the next round, and the order test: the review that starts first and finishes last (a Codex stub that sleeps on its first call only) gets the higher number and its comment is posted last
