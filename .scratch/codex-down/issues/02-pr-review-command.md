# 02: PR review becomes a command

**What to build:** today the PR gate is prose in the boss skill: each worker types `codex exec` by hand. This ticket gives the worker one command, `skills/boss/boss_review.py`, that reviews one PR head. It runs Codex read-only through 01's chain (Codex only: the fallback is 08's), numbers and keeps each round on disk outside the repo, and posts a minimal `Codex review N (run by <name>)` comment on the PR with the head SHA and the verdict. Every outage now passes through one place where it can be seen and counted.

Command and function:

- [x] `boss_review.py --repo OWNER/REPO --pr N --checkout DIR --author NAME`. Exit codes: 0 GO posted, 2 usage, identity mismatch or an invalid name, 3 NO-GO posted, 4 no verdict (Codex `absent`, `timeout`, `error` or `noverdict`), 6 head or base moved, 7 infrastructure failure (the cases below). Exit 5 is 09's (`--waive` refused) and is never used here. `--repo` is required and never inferred from the working directory; `<owner>`, `<repo>` and `--author` match `^[A-Za-z0-9._-]+$`, and `<owner>` and `<repo>` are neither `.` nor `..` (the pattern alone lets `..` through), else exit 2 with nothing claimed or posted; tests: `../x`, `x/..`, `./x`, `a/b/c` [R7, R9]. GitHub treats owner and repo names case-insensitively, so one function, `repo_key(repo)` (`<owner>/<repo>` lowercased), gives the key used for the directory name, the per-PR lock, the `repo` value of `round<NN>.json`, `attempts.jsonl` and 04's `merges.jsonl`, and the tag of 06's entry; the `gh` calls carry the spelling given. 04, 06 and 10 call `repo_key` and never build a path from `--repo` as typed
- [x] The logic is a function the CLI wraps: `review(repo: str, pr: int, checkout: str, author: str, *, codex_timeout: int = REVIEW_CODEX_TIMEOUT, io_timeout: int = REVIEW_IO_TIMEOUT) -> ReviewResult`, with `ReviewResult` a frozen dataclass `(exit_code: int, round: int | None, status: str | None, verdict: str | None, record: Path | None)`: `exit_code` is what the CLI exits with, `round`, `status` and `verdict` are the claimed round's values, `record` is the path of its `round<NN>.json`, and all four are `None` when no round was claimed. When a failure after the claim leaves the claimed file empty (the attempts append, the `.out` write or the final write failing: exit 7 below), `round` and `record` name the claimed file and `status` is `None`. An argument that fails its check (a name, a `pr` that is not a positive integer, a `checkout` that is not a directory) raises `ValueError`, which the CLI turns into exit 2 with the message on stderr; every other outcome, an identity mismatch and exit 7 included, is a `ReviewResult`, never an exception. The three constants are added to `policy.py`: `REVIEW_CODEX_TIMEOUT = 600` and `REVIEW_FALLBACK_TIMEOUT = 600` (a Codex review of this plan took 8 minutes; 03 uses the second) and `REVIEW_IO_TIMEOUT = 60` [R3 in part]. Later tickets extend the signature with keyword-only parameters that have defaults: 05 `track`, 08 `fallback_timeout` and `allow_fallback`, 10 `head_sha`; 10's recheck calls the function and reads the result (no second copy)

Identity, head and the chain:

- [x] Identity and head come from one read, `gh pr view N --repo R --json number,url,headRefOid,baseRefName`. Identity holds iff `number == N` and the URL path is `/<owner>/<repo>/pull/<N>` with owner and repo compared case-insensitively with `--repo`; else exit 2, nothing claimed, nothing posted. `gh pr view` exiting non-zero, printing something that is not JSON, or lacking a field: exit 7, nothing claimed. `--checkout`'s HEAD must equal `headRefOid` (else exit 2, nothing claimed). Every `gh pr` call carries `--repo`; every `gh api` endpoint starts `repos/<owner>/<repo>/` with the validated names; both are asserted from the `gh` stub's call log [R5, R7]. Each `gh` call and the lock wait below are bounded by `io_timeout`; a timeout is exit 7
- [x] The chain call is 01's `run_chain`, Codex only (no fallback), `words` for `GO`/`NO-GO`, the strict flag on, `codex_timeout`. `run_chain` has no working-directory parameter and 01 is not changed, so `review()` runs it in a child process started with its working directory set to `--checkout` (01's chain CLI, or a child that imports the module: the builder chooses and the PR says which), and every reviewer inherits that directory. At this ticket the brief is a fixed text from `build_brief(head_sha, base)`: the head SHA and the base branch, an instruction to review the checked-out head against the base without changing anything, and the answer format (`FINDING:` lines, then one final `VERDICT: GO` or `VERDICT: NO-GO` line). It holds no PR title, body or diff; 07 replaces it with the fenced PR text. A test reads the working directory the `codex` stub recorded and it equals `--checkout`

Rounds and the record:

- [x] Per round, under `$CLAUDE_CONFIG_DIR/pm/reviews/<owner>/<repo>/pr<N>/`: `round<NN>.json` and `round<NN>.out`, with directories 0700 and files 0600 (an existing directory or file with wider modes is tightened when the command uses it), never under `--checkout`; the command deletes nothing. `round<NN>.out` holds the answering attempt's full output; when no reviewer answered, each attempt's raw output under a line `--- <reviewer> <reason> ---`. Every attempt of every run, answered or not, also appends one line to `pm/reviews/attempts.jsonl` in a single `O_APPEND` write [R9]. Exact schemas: `round<NN>.json` has these keys and no others: `repo` (string), `pr` (int), `round` (int, equal to the file's number), `head_sha`, `base`, `reviewer` (`"codex"` when Codex answered, `"none"` when no reviewer answered; 08 adds `"opus"`, 09 `"tests"`), `model` (`null` in this ticket; 08 sets the fallback's id), `kind` (`"codex"` | `"provisional"` | `"waived"`; 02 writes `codex`, 08 adds `provisional`, 09 `waived`), `verdict` (`"GO"` | `"NO-GO"` | `null`), `status` (`"posted"` | `"head-moved"` | `"no-verdict"` | `"post-failed"` | `"list-failed"`; 02 writes the first four, `list-failed` is 06's), `author`, `ts` (UTC, ISO-8601 with `Z`) and `attempts` (a list of objects with the keys `reviewer`, `reason`, `exit_code`, `stderr_tail`, `model`: 01's `Attempt` without `output`, every key present, `null` where 01's value is `None`); 09 adds `tests` for a waived round. An `attempts.jsonl` line has exactly the keys `ts`, `repo`, `pr`, `round`, `reviewer`, `reason` (01's closed set) and `exit_code` (01's `Attempt.exit_code`: an int, or `null` for `absent` and `timeout`), and no output text. 05 reads `reviewer` and `reason`

The order, and what a failure leaves:

- [x] The review runs first; the round is claimed at the end of the run, whatever the outcome (GO, NO-GO, no verdict, head moved). The command takes a `flock` on `pr<N>/.lock` (0600), re-reads the live head and base (`headRefOid` and `baseRefName`), claims the next free `round<NN>.json` with `O_CREAT|O_EXCL`, appends the run's attempts (each line now carries the round number), writes `round<NN>.out`, posts, replaces the claimed file with the full JSON by temp file and rename, and releases the lock. So numbers follow posting order and each comment's number equals its file's; which round decides is 04's scan, not a rule of this ticket. A head or a base that differs from the one the review ran on at the re-read: exit 6, nothing posted, round `head-moved` (the status covers both; the record's `base` is the base the review ran on, and 04 requires it to equal the live base). The window between that re-read and the comment is not closed: the comment and the record name the head the review ran on, and 04's gate, which needs a `posted` GO on the live head, is what keeps a moved head from merging [R5, R6]
- [x] Exit 7 and what each leaves. `gh pr view` failed, or the claim itself failed (the lock or the round directory unwritable): nothing is claimed or posted, and the result's `round`, `status`, `verdict` and `record` are `None` (the table below gives every field of every outcome). A failure after the claim, in the attempts append, the `.out` write or the final write, leaves the claimed file empty, which 04 reads as `bad-record` and the next round supersedes; the result has `status` `None` with `round` and `record` naming that file, and when the failure comes before the post, nothing is posted. `gh pr comment` failed or timed out: round `post-failed`, the verdict kept in the JSON. When the chain gives `none`: exit 4, nothing that reads as a verdict is posted, the round is `no-verdict`, the attempts are logged. The comment is `Codex review N (run by <name>)`, the head SHA and the verdict, no free text. **The record, not the comment, is what the gate reads:** a round is `posted` only after `gh pr comment` returned success, so a comment on the PR with no `posted` record behind it authorizes nothing. Two states can leave a public comment beside a record that is not `posted`, and both are refused by 04: a comment call that failed after GitHub had accepted the comment (`post-failed`), and a final write that failed after a good post (the claimed file stays empty, which 04 reads as `bad-record`). A retry is a new review and a new round with a higher number; no round file is edited after its final write [finding 4 of review 4]

  The `ReviewResult` for every outcome (`None` is Python's `None`; the record's `verdict` is the chain's verdict whenever the chain gave one, and is kept in the JSON even when nothing is posted):

  | Outcome | `exit_code` | `round` | `status` | `verdict` | `record` |
  |---|---|---|---|---|---|
  | GO posted | 0 | N | `posted` | `GO` | path |
  | NO-GO posted | 3 | N | `posted` | `NO-GO` | path |
  | the chain gave no verdict | 4 | N | `no-verdict` | `None` | path |
  | head or base moved | 6 | N | `head-moved` | the chain's verdict or `None` | path |
  | `gh pr comment` failed or timed out | 7 | N | `post-failed` | the chain's verdict | path |
  | the attempts append, the `.out` write or the final write failed (claimed file empty) | 7 | N | `None` | the chain's verdict or `None` | path |
  | `list-failed` (06) | 7 | N | `list-failed` | `GO` | path |
  | `gh pr view` failed, or the claim failed (lock or directory) | 7 | `None` | `None` | `None` | `None` |
  | identity mismatch, checkout HEAD mismatch | 2 | `None` | `None` | `None` | `None` |
