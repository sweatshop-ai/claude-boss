The recheck (R17, R18):

- [ ] `skills/boss/boss_recheck.py --track T --repo OWNER/REPO --checkout DIR [--author NAME]` (`--author` defaults to `recheck` and matches 02's name rule) takes the entries of that repo (`provisional_entries` of the tracker `codex_blocker.usable_tracker(T, "rechecked")` returns, matched by 02's `repo_key`; an unusable track is exit 2 and stderr says `no blocker can be rechecked`, which a test reads) one at a time with no entry able to stop or erase another, calls `prune_provisional` at the start of the pass and after each review, and for each entry calls `review(...)` with `allow_fallback=False` and `track=T` (so 05c's health sync runs): a merged PR in a worktree at its merged `headRefOid` (not the entry's `head=`, see the merged-head box below), a PR that is `CLOSED` without a merge not at all, an open PR in a worktree at its live head. The review always runs in a detached temporary worktree outside `--checkout` (`git fetch origin refs/pull/<N>/head`, which GitHub keeps for open, merged and closed PRs, the branch being gone or advanced after a merge, then `git worktree add --detach` at the SHA `_live_state` read, `FETCH_HEAD` and HEAD verified equal to it, removed afterwards even when the review fails, leftovers pruned at the start of a pass), so a deleted or advanced branch cannot change what is reviewed and the shared checkout is never moved. Outcomes: a Codex GO leaves the entry to `prune_provisional`; a Codex NO-GO (`result.verdict` `NO-GO` with `status` `posted` or `post-failed`: an unposted NO-GO is still a NO-GO, as 04's `unposted-no-go` says) on an open PR leaves the entry and prints `NO-GO <repo>#<N> round <NN> author=<name>` for the boss to dispatch (`<name>` is the `author` of the entry's own round); no Codex answer (any other exit of `review()`: 4, 6, 7, a `head-moved`, `no-verdict` or `list-failed` status, a round left empty), a fetch that fails, or a `gh pr view` that fails (`_live_state` gives None) leaves the entry and goes on to the next one; the entry then still counts for `--list`. A leftover round file that `prune_provisional` cannot read, or that is empty, keeps its PR's entry; the next review of that PR clears it, because the prune skips an empty round that has a later round above it as a dead claim (ticket 25, second box, built and tested; the newest round empty still keeps the entry). The recheck needs no change for this: it writes a later round
- [ ] A Codex NO-GO on a merged PR (R20) writes an open blocker first, then removes the entry itself (the one case where a NO-GO removes an entry). The removal is one `tracker.update` (`tracker.py:350`) that removes only the exact `ProvEntry` line the pass read, compared as a whole line and not by the PR's tag, so an entry replaced between the read and the removal (a newer round's entry for the same PR) is left alone; and it runs only after `add_line` answered `done` or `done (already there)`, or after the whole-file search above found the round's id. A blocker write that answers `failed: ...` leaves the entry (the release stop holds) and is said on stderr. The blocker is one line under the first `## Open blockers`: `- Codex NO-GO on merged <repo>#<N> (round <NN>) - T+0 <ts> [ladder id=fx<8 hex of sha1 of "<repo>#<N> round <NN>"> t0=<ts> last=0 next=<t0 + 5 min> ask="<action>"]` (`tracker.render_marker(id_, t0, nxt, ask=...)`, `tracker.py:207`; `policy.RUNGS[0]` is the 5 minutes; the id is `fx` and 8 hex digits, which `tracker.ID_RE` takes), `<NN>` being the number of the NO-GO round just claimed. **The id is per round, not per PR (ticket 16, finding 4, decided here):** `tracker.add_line` (`tracker.py:417`) counts a tag as there only on a line without a `cleared=` value, so that a cleared blocker does not hide a new one with the same id. That makes an id made from the PR alone wrong (a second NO-GO on the same PR would reuse it) and it also means `add_line` alone cannot make a retry of the same round idempotent once that round's blocker was cleared. So the id is per round (a second NO-GO is a new round and a new id), and the recheck itself makes the retry idempotent: before it calls `add_line` it reads the tracker and treats any occurrence of the exact per-round id as whole token anywhere in the file, a cleared line included, as handled (no new line, no alert, and the entry may be removed). It is written with 05a's `tracker.add_line(path, tracker.BLOCKERS, line, tracker.marker_tag(id_), deadline)`, and `boss-alert 0` is called once, only when `add_line` answers `done` (not `done (already there)`), through `codex_blocker.default_alert()`. `<action>` names the PR and the round's `.out` file under `pm/reviews/<repo_key>/pr<N>/` (`round<NN>.out`, beside the record `ReviewResult.record`) and says to dispatch its author or any free worker. The recheck prints `DISPATCH <repo>#<N> author=<name> round=<NN>`, `<name>` being the `author` of the entry's own round. **Crash and resume:** the blocker is written before the entry is removed, so a crash between the two leaves the entry. Before it reviews a merged entry, the recheck looks at the highest `kind: codex` round on the merged head with status `posted` or `post-failed` (the two statuses the NO-GO outcome above counts) that is numbered above the entry's `round=`: if that round is a NO-GO, it does not review again, it adds the blocker for that round (a no-op when it is there) and removes the entry. So the next pass neither adds a second blocker nor claims a new round. The blocker is the guaranteed minimum: the ladder raises it with no boss turn even when no author session exists, and it stays open until the fix has merged on a Codex GO, then the boss sets `cleared=` and posts `boss-alert clear`
