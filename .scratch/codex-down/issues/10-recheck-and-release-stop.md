# 10: Codex re-reviews every provisional GO, and a release waits for it

**What to build:** when Codex answers again, each PR on 06's provisional list gets a Codex review on the head that was reviewed (an open PR) or merged (a merged PR, reviewed in a detached worktree). A Codex NO-GO on a merged PR becomes a dispatched fix, or an open blocker on the ladder when no author can take it. A release or wrap-up stops while the list is not empty. Recovery is Codex-only: a re-review never falls back to Claude.

**Scope:** new on 2026-10-04, split out of the original ticket 06 after Codex review 3 of the plan (finding 23), with the owner-accepted premortem (R16 to R18, R20, R25). The list, its write and its removal rule are 06's (`prune_provisional`); this ticket adds the command that walks the list and the skill text that makes the boss run it. It does not wait for 04: it reads and writes nothing that `boss_merge.py` owns.

**Blocked by:** 06 (Provisional GOs are tracked in a list that survives restarts)

**Status:** ready-for-agent

The review function (R17):

- [ ] `boss_review.review(...)` gains two optional parameters after 05's `track`: `head_sha`, a fixed commit to review (the PR's live head is then not compared with it, because a merged PR's head is no longer the thing being decided; the checkout's HEAD must still equal it, and the brief, the round record and the comment name it) and `allow_fallback` (default true; the recheck passes false). The CLI is unchanged. Tests: a merged PR whose live head differs from the reviewed SHA is reviewed and posted; an open PR with no `head_sha` still exits 6 when its head moves; with `allow_fallback=False` and a failing Codex the `claude` stub's call log stays empty

The recheck (R17, R18):

- [ ] `skills/boss/boss_recheck.py --track T --repo OWNER/REPO --checkout DIR [--author NAME]` (`--author` defaults to `recheck` and matches 02's name rule) takes the entries of that repo one at a time with no entry able to stop or erase another, calls `prune_provisional` at the start of the pass and after each review, and for each entry calls `review(...)` with `allow_fallback=False` and `track=T` (so 05's health sync runs): a merged PR with `head_sha=<the entry's head=>`, an open PR without `head_sha`, so it is reviewed on its live head. The review always runs in a detached temporary worktree outside `--checkout` (`git fetch origin <sha>`, `git worktree add --detach`, HEAD verified equal to the SHA, removed afterwards even when the review fails, leftovers pruned at the start of a pass), so a deleted or advanced branch cannot change what is reviewed and the shared checkout is never moved. Outcomes: a Codex GO leaves the entry to `prune_provisional`; a Codex NO-GO on an open PR leaves the entry and prints `NO-GO <repo>#<N> round <NN> author=<name>` for the boss to dispatch (`<name>` is the `author` of the entry's own round); no Codex answer, or a fetch that fails, leaves the entry and goes on to the next one
- [ ] A Codex NO-GO on a merged PR (R20) writes an open blocker first, then removes the entry itself (the one case where a NO-GO removes an entry), so a crash between the two leaves the entry and the next pass finds the blocker and does not add another. The blocker is one line under the first `## Open blockers`: `- Codex NO-GO on merged <repo>#<N> (round <NN>) - T+0 <ts> [ladder id=fx<8 hex of sha1 of "<repo>#<N>"> t0=<ts> last=0 next=<t0 + 5 min> ask="<action>"]`, built with `tracker.render_marker`, written with `tracker.add_line` (dedupe on the marker's id), followed by `boss-alert 0` once. `<action>` names the PR and the round's `.out` file under `pm/reviews/` and says to dispatch its author or any free worker. The recheck prints `DISPATCH <repo>#<N> author=<name> round=<NN>`. The blocker is the guaranteed minimum: the ladder raises it with no boss turn even when no author session exists, and it stays open until the fix has merged on a Codex GO, then the boss sets `cleared=` and posts `boss-alert clear`

Trigger and release stop (R16):

- [ ] `skills/boss/SKILL.md` says: run `boss_recheck.py` for each repo that has entries whenever a Codex review answers and at wrap-up; on a `DISPATCH` line, dispatch the author or any free worker with the round file as the brief; **wrap-up (Phase E) and any release request (a version bump, a tag, a publish, a reinstall) stop while the list is not empty**, and the boss tells the owner which PRs. `boss_recheck.py --track T --list` prints the entries and exits 0 when there are none and 1 when there are. A text test finds the trigger, the dispatch rule and the stop; a command test checks both exit codes

Tests:

- [ ] Tests use real `git` in throwaway repos with a local bare origin, and 01's stub-directory harness with its PATH guard (`codex`, `claude`, `gh` and `boss-alert` stubs, a temp `HOME` and `CLAUDE_CONFIG_DIR`, `BOSS_TYPESAFE_ENV` pointing at a missing file): each test asserts its stub call logs, that the `claude` log is empty in every recheck test, and fails if `codex`, `claude` or `gh` resolves outside the stub directory [R25]. Cases: three entries where the middle review times out (the other two are handled and the middle stays); a merged PR whose branch was advanced or deleted after the record (the stub's working directory HEAD equals the recorded SHA, the shared checkout's HEAD and files are unchanged, the temporary worktree is gone); a fetch that fails; a Codex NO-GO on an open PR prints its `NO-GO` line and keeps the entry; a Codex NO-GO on a merged PR gives a blocker that passes `tracker.scan_marker`, `tracker.validate` and `tracker.blockers_range`, that `routines/boss_ladder_core.py --now <t0 + 6 minutes>` raises at rung 5, and a `DISPATCH` line; a crash between the blocker and the removal (blocker already present) adds no second one
