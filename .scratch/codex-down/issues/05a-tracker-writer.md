The tracker writer (R23, finding 5):

- [ ] `tracker.py` gains `update(path, fn, deadline)` and `add_line(path, title, line, tag, deadline)`, and `mark_cleared(raw, when)` beside them. `update` takes the sibling lock from `tracker.lock_path` with `flock` until `deadline` (a `time.monotonic()` value; polled with `LOCK_NB`, so a held lock is a return value and not a hang), reads the file, calls `fn(text)` for the new text or `None` for no change, and writes by temp file named `.boss-tracker-*` in the tracker's directory and `os.replace` with the file mode kept, at most 3 tries in all, as the ladder (`for attempt in range(3)`), when the file's `(st_mtime_ns, st_size)` changed between the read and the write (the boss's Edit tool takes no lock, and the ladder's `process_tracker` makes the same check with the same limit). It returns `"done"`, `"done (no change)"` (`fn` returned `None`) or `"failed: <reason>"` (the lock held past the deadline, the file changed on all 3 tries, or the name of an `OSError`), and never raises for those; an exception from `fn` itself is not swallowed. `add_line` adds `line` under the section `title` (created when missing, by `tracker.insert_in_section`) unless `tag` is already in the file, in `update`'s one locked step, and returns `"done"`, `"done (already there)"` or `"failed: ..."`. `mark_cleared(raw, when)` (`when` a timezone-aware `datetime`; a naive one is a `ValueError`, because `tracker.parse_ts` refuses it and the ladder would report the marker malformed) takes a line, finds its marker with `scan_marker`, and returns the line with ` cleared=<when ISO, minutes>` inserted before ` ask=` (where the ladder's own fixtures put it), byte for byte elsewhere; a line with no readable marker or one that already has `cleared=` is returned unchanged. (2026-11-12: this is new code, not the move of `boss-jev.py`'s `tracker_add`, which is gone; `test_boss_jev.py` no longer exists, so "passes unchanged" is dropped. `test_tracker.py` gains the tests below.) Tests: each return value of `update` (including a lock held by another process past a 0.2 s deadline, and a `fn` that makes the file change itself on every call, which asserts `fn` was called 3 times), the mode kept, `.boss-tracker-*` temp files left behind none, `mark_cleared` read back with `scan_marker`/`validate` (`fields["cleared"]` set, `last` and `next` unchanged) and a no-marker line unchanged, and eight concurrent processes calling `add_line` with one tag give one line while `boss-tracker append` writers run beside them and lose nothing. 06 and 10 reuse `update` and `add_line`; 05c and 09 reuse `mark_cleared`
