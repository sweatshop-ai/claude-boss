# 06b: Provisional entries are removed when Codex has since said GO

**What to build:** `prune_provisional(track, repo)`, the one function that removes an entry from 06a's list, and the three rules that say when. Ticket 10's recheck calls it at the start of every pass and after each review in it; nothing else does.

**Scope:** split out of 06 on 2026-11-12 (Lucia, task #06S, on Chiara's ruling, `plan-review-codex-06-1.md` finding 11). The box is the old 06's removal box with the removal rows of its Tests box moved into it, so the count stays six across 06a and 06b. It needs only 06a's list format (the `- [prov owner/repo#N] head=... round=... base=... at=...` line under `## Provisional GO`), the round files 02 and 08 write, and `tracker.update` (05a).

**Blocked by:** 06a (Provisional GOs are written to a list that survives restarts), and through it 05a, 05c, 08 and 14

**Status:** in progress (Marit, PR for 06b, 2026-11-12; spec refreshed 2026-11-12; Codex spec round 1 in `plan-review-codex-06-1.md`)

Removal:

- [x] A function `prune_provisional(track, repo)` in `skills/boss/boss_review.py` removes an entry, inside one `tracker.update`, in four cases (rules 1, 2 and 4 remove; rule 3 is the rule that keeps a CLOSED PR's entry). A PR whose state cannot be read (`gh pr view` fails) keeps its entry under every case below, rule 1 included; so does a PR with an unreadable, empty or unparseable round file (the function takes no PR lock, so it can read a round that is claimed and not yet recorded: that file is skipped, and 04 calls it `bad-record`). Its caller is 10's `boss_recheck`, not `_keep_and_post`. Rule 1: when the highest-numbered posted round of that PR with `kind` `codex` **and** a `head_sha` equal to the entry's `head=` is a `GO` with a number above the entry's `round=` (Codex has since said GO on the head that was reviewed, and no later Codex round on it says otherwise). Rule 2: for an entry whose PR is open and whose live head differs from the entry's `head=` (read with `gh pr view --repo R --json state,headRefOid`; the round files are `reviews/<repo_key>/pr<N>/round<NN>.json`, read as `_keep_and_post` writes them) it removes the entry when the highest-numbered posted `kind: codex` round on the live head is a GO with a number above the entry's `round=` (added 2026-11-12, Opus fallback review 3: a force-push back to a head cleared before the provisional round must not drop the entry; rule 4 has no such condition, a merge being final) (an older Codex GO on the entry's own head never removes through this rule: rule 1's "above the entry's round" is the only test there), because the entry's head no longer merges. A Codex GO on a later head never removes the entry of a merged PR (finding 16); a Codex NO-GO never removes an entry through this function (10's post-merge blocker removes its own entry after writing the blocker); a PR whose state cannot be read keeps its entry. Rule 3 (replaced 2026-11-12, spec round 3 finding 1): a PR whose state is `CLOSED` without a merge **keeps its entry**. Removing it would let a reopened PR merge on its old provisional round with no entry (case C of 22). The entry is the record that the PR holds only a loan; while the PR is `CLOSED`, 10's recheck does not review it and 10's release stop does not count it (22 adds that to 10); when the PR is reopened the entry is live again and every other rule applies. Rule 4: for a `MERGED` PR whose `headRefOid` differs from the entry's `head=` (case B of 22), the highest-numbered posted `kind: codex` round on the merged `headRefOid` being a `GO` removes the entry, inside the same `update`, because the merged head is now Codex-reviewed; a NO-GO there never removes it (10's post-merge blocker does, after writing the blocker); an unreadable record or a failed review leaves it. An entry whose head equals the merged head is covered by rule 1. 10's recheck calls it at the start of every pass and after each review in it. `fn` does no I/O: the PR states and the round records are read first, and `fn` removes only the entries whose line is still the one that was read. Once 16 finding 3 is built, an exception raised in `fn` of any kind propagates out of `update` with the tracker file and lock unchanged (`update` writes only what `fn` returns); `prune_provisional` lets it propagate to `boss_recheck`, which reports it and goes on to the next entry (10). The function takes the tracker's lock and never the PR's lock (`_keep_and_post` takes the PR's lock and then the tracker's, never the other order). It returns the removed tags. Tests (use 06a's harness: real `git` where a checkout is needed, the stub-directory harness with its PATH guard, a temp `HOME` and `CLAUDE_CONFIG_DIR`, and a tracker written by hand in 06a's line format): each removal row (GO on the entry's head and a later round removes; that GO followed by a later Codex NO-GO on the same head keeps; GO on a later head of a merged PR keeps; the same GO on an open PR removes; NO-GO keeps; an unreadable PR state keeps, also when a Codex GO above the entry's round on its head exists; a CLOSED unmerged PR keeps its entry, also with a Codex GO above the entry's round on its head (case C), and the same PR reopened and then reviewed by Codex with a GO removes it by rule 1; a MERGED PR whose merged head differs from the entry's, with a Codex GO on the merged head, removes by rule 4, and with a NO-GO or no round keeps; an older Codex GO on the entry's head, with the live head the same, does not remove through rule 2).
