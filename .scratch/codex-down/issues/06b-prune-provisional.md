# 06b: Provisional entries are removed when Codex has since said GO

**What to build:** `prune_provisional(track, repo)`, the one function that removes an entry from 06a's list, and the three rules that say when. Ticket 10's recheck calls it at the start of every pass and after each review in it; nothing else does.

It needs only 06a's list format (the `- [prov owner/repo#N] head=... round=... base=... at=...` line under `## Provisional GO`), the round files 02 and 08 write, and `tracker.update` (05a).

**Blocked by:** 06a (Provisional GOs are written to a list that survives restarts), and through it 05a, 05c, 08 and 14

**Status:** ready-for-agent (spec refreshed 2026-11-12; Codex spec round 1 in `plan-review-codex-06-1.md`)

Removal:

- [ ] A function `prune_provisional(track, repo)` in `skills/boss/boss_review.py` removes an entry, inside one `tracker.update`, in three cases. A PR whose state cannot be read (`gh pr view` fails) keeps its entry under every case below, rule 1 included. Rule 1: when the highest-numbered posted round of that PR with `kind` `codex` **and** a `head_sha` equal to the entry's `head=` is a `GO` with a number above the entry's `round=` (Codex has since said GO on the head that was reviewed, and no later Codex round on it says otherwise). Rule 2: for an entry whose PR is open and whose live head differs from the entry's `head=` (read with `gh pr view --repo R --json state,headRefOid`; the round files are `reviews/<repo_key>/pr<N>/round<NN>.json`, read as `_keep_and_post` writes them) it removes the entry when the highest-numbered posted `kind: codex` round on the live head is a GO (an older Codex GO on the entry's own head never removes through this rule: rule 1's "above the entry's round" is the only test there), because the entry's head no longer merges. A Codex GO on a later head never removes the entry of a merged PR (finding 16); a Codex NO-GO never removes an entry through this function (10's post-merge blocker removes its own entry after writing the blocker); a PR whose state cannot be read keeps its entry. Rule 3: a PR whose state is `CLOSED` without a merge (it will never merge; `gh pr view --json state` says `CLOSED`, a merged one says `MERGED`) loses its entry, since neither 10's recheck nor rule 1 can reach it and 10's release stop would never lift (a reopened PR gets a new entry from its next provisional GO). 10's recheck calls it at the start of every pass and after each review in it. `fn` does no I/O: the PR states and the round records are read first, and `fn` removes only the entries whose line is still the one that was read (16 finding 3: `update` turns only an `OSError` or `UnicodeDecodeError` from `fn` into `failed`; any other exception escapes `_keep_and_post`, which catches `OSError` only, and leaves an empty round). The function takes the tracker's lock and never the PR's lock (`_keep_and_post` takes the PR's lock and then the tracker's, never the other order). It returns the removed tags. Tests (use 06a's harness: real `git` where a checkout is needed, the stub-directory harness with its PATH guard, a temp `HOME` and `CLAUDE_CONFIG_DIR`, and a tracker written by hand in 06a's line format): each removal row (GO on the entry's head and a later round removes; that GO followed by a later Codex NO-GO on the same head keeps; GO on a later head of a merged PR keeps; the same GO on an open PR removes; NO-GO keeps; an unreadable PR state keeps, also when a Codex GO above the entry's round on its head exists; a CLOSED unmerged PR removes; an older Codex GO on the entry's head, with the live head the same, does not remove through rule 2).
