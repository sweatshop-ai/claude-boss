- [x] **A prose line holding the tag counts as "already there" (class c).** `add_line` (`tracker.py`, `there`) takes any line of the section that holds the tag and has no marker as present, so a note `- resolved id=ab12cd34, see PR 90` in `## Open blockers` hides a new blocker with that id; a malformed marker holding the tag does the same. The docstring says prose does not count. Decide (count only lines with a readable marker, or document it) and test. No production caller yet; ticket 10 should use `marker_tag(id)`. Decided: documented, not changed. `add_line`'s tag is the caller's, and the generic callers pass bare tags on lines that carry no marker (`AddLine` tests), so counting only readable markers would break them. A caller that means "the marker with this id" passes `marker_tag(id)`, which holds `[ladder id=… ` and is not found in prose; a malformed marker holding the tag stays "there" on purpose (never a second line beside a hand-damaged one). The docstring says so; `test_marker_tag_is_not_found_in_prose_and_a_bare_tag_is_found_in_any_line` and `test_a_malformed_marker_holding_the_tag_is_there` pin both.
- [x] **CRLF file without a final newline gets mixed endings (class c).** `insert_in_section` on `"## Open blockers\r\n- a"` yields `"...\r\n- a\nnew\r"`. Add the `\r` to the last line's break when the file has none at its end; test. Done: `insert_in_section` gives the last line its `\r` and leaves the new one bare, so the file ends as it did. `test_a_crlf_file_without_a_final_newline_keeps_one_ending`, `test_an_lf_file_without_a_final_newline_is_unchanged`.
- [x] **Readers that do not pin the encoding (class c).** `boss_review.py` `_listed` and `prune_provisional` open the tracker with the locale encoding, and `routines/boss_ladder_core.py` reads and writes with it, while `tracker.update` is now UTF-8. Under a non-UTF-8 locale the ladder rewrites the file as that encoding and every later `update` returns `failed: UnicodeDecodeError`. Pin `encoding="utf-8"` in those places; test under `LC_ALL=C` with coercion off. Done: `encoding="utf-8"` on the two openers in `boss_review.py` (`_listed`, `prune_provisional`) and on the ladder's `read_text` and its temp-file write. `ReadersPinUtf8` runs both under `LC_ALL=C`, coercion and UTF-8 mode off, and fails on the old code. Not touched: `boss_store.py` line 140 reads a goal file with `errors="replace"` (not a tracker), and the ladder's alert text goes through argv, which a C locale cannot encode (parked, not ticketed).
- [x] **`update` drops an exception's cause (class d).** `raise raised.args[0] from None` clears the `__cause__` of an `OSError` that `fn` raised `from inner`. Re-raise without touching the cause. Done: `update` collects `fn`'s exception and raises it after the handler, so its `__cause__` and `__suppress_context__` stand. `test_an_exception_from_fn_keeps_its_cause`.
- [x] **ASCII boundary, Unicode test (class d).** `add_line` switches its word boundary on `tag[0].isalnum()`, which accepts non-ASCII letters, while the boundary class is ASCII-only. Use the same class for both. Done: the boundary test and the boundary class are both ASCII (`[A-Za-z0-9]`). `test_a_non_ascii_edge_of_the_tag_gets_no_word_boundary`.
