The waiver:

- [ ] `boss_review.py --waive --repo OWNER/REPO --pr N --checkout DIR --author NAME --track T --test-cmd "<cmd>"` (`--author` as in the review command; `--waive` is a mode that replaces the review as `--check-fallback` does and refuses the flags it does not take). `<cmd>` is run as `["/bin/sh", "-c", cmd]` through `_spawn` with `cwd` the checkout, stdin closed and the caller's environment, within `policy.WAIVE_TEST_TIMEOUT = 900` seconds (a new constant; a timeout counts as failed tests and `_spawn` stops the children too). `--waive` calls `_prepare` (`boss_review.py:922-938`): an identity mismatch or a wrong checkout is exit 2, a reviews directory inside the worktree 7. The checkout must be clean: `git -C DIR status --porcelain` (untracked files included) is empty before the tests and again under the lock, else exit 5 before; a checkout that turns dirty during the tests is exit 6 with a round of status `head-moved` and `verdict` `GO` (the checkout moved), nothing posted (`_checkout_of` reads only HEAD, `boss_review.py:352-367`, so uncommitted files would otherwise be tested and the waiver would claim a head that fails; N6). Residue for `coverage.md` R26: `--test-cmd` is the caller's, so `true` passes; the `CONSENT:` question names the command the boss will run. Then, under the PR's lock (`open_lock`, `claim_round`, `replace_record`, as `_keep_and_post`), re-read the live head and base, the checkout's HEAD and `choice(T)` (finding 8: the tests run up to 900 seconds and the owner or recovery may have changed the blocker meanwhile): all must be what they were before the tests, the same blocker id and still `tests-alone`. The tracker is only read, never locked, in that step: the PR lock is the outer lock and no tracker lock is taken while it is held.
