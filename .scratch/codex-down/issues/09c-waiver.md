# 09c: The waiver: merge on tests alone, only through `--waive`

**What to build:** "merge on tests alone" is never a loose sentence: it is `boss_review.py --waive`, which records a `waived` round only when the owner chose it with their own consent, the tests pass on the head, and the head has not moved. 04's gate then lets a waived round merge only on a branch the repo lists as non-deploying.

**Scope:** split out of 09 (the waiver half), refreshed against `main` f0ae63d and amended by Codex spec round 1 findings 1, 8 to 11 (`plan-review-codex-09-1.md`). It writes `kind: waived` into the round record 02 defines; a waived merge is not put on 06's list and Codex does not re-review it.

**Blocked by:** 09b (the record and `codex_blocker.choice`), 08 (merged)

**Status:** ready-for-agent

The waiver:

- [ ] `boss_review.py --waive --repo OWNER/REPO --pr N --checkout DIR --author NAME --track T --test-cmd "<cmd>"` (`--author` as in the review command; `--waive` is a mode that replaces the review as `--check-fallback` does and refuses the flags it does not take). `<cmd>` is run as `["/bin/sh", "-c", cmd]` through `_spawn` with `cwd` the checkout, stdin closed and the caller's environment, within `policy.WAIVE_TEST_TIMEOUT = 900` seconds (a new constant; a timeout counts as failed tests and `_spawn` stops the children too). `--waive` calls `_prepare` (`boss_review.py:922-938`): an identity mismatch or a wrong checkout is exit 2, a reviews directory inside the worktree 7. The checkout must be clean: `git -C DIR status --porcelain` (untracked files included) is empty before the tests and again under the lock, else exit 5 before and 6 after (`_checkout_of` reads only HEAD, `boss_review.py:352-367`, so uncommitted files would otherwise be tested and the waiver would claim a head that fails; N6). Residue for `coverage.md` R26: `--test-cmd` is the caller's, so `true` passes; the `CONSENT:` question names the command the boss will run. Conditions, the three cheap ones first and the command only when they held: `codex_blocker.choice(T)` is `chosen` with `tests-alone`; `--checkout`'s HEAD (`_checkout_of`) equals the live PR head (`_read_pr`); the command exits 0. Then, under the PR's lock (`open_lock`, `claim_round`, `replace_record`, as `_keep_and_post`), re-read the live head and base, the checkout's HEAD and `choice(T)` (finding 8: the tests run up to 900 seconds and the owner or recovery may have changed the blocker meanwhile): all must be what they were before the tests, the same blocker id and still `tests-alone`. The tracker is only read, never locked, in that step: the PR lock is the outer lock and no tracker lock is taken while it is held.
- [ ] The record has the keys `_keep_and_post` writes (`repo`, `pr`, `round`, `head_sha`, `base`, `reviewer`, `model`, `kind`, `verdict`, `status`, `author`, `ts`, `attempts`) with `kind` `waived`, `verdict` `GO`, `reviewer` `tests`, `model` null, `attempts` `[]` and one more key `tests: {cmd, exit: 0}` (`cmd` through `redact`); `head_sha` and `base` are those read before the tests. The comment is `Merge on tests alone (Codex unavailable): <cmd> passed on <head SHA>`, `<cmd>` through `redact`, posted with `_post`. A refusal (5) records and posts nothing. A `--waive` run appends nothing to `attempts.jsonl`, so Codex's health count is unchanged.
